# Shenoll ERP

Система производственного и складского учёта. Бэкенд — Django без DRF,
PostgreSQL и Django Channels; фронтенд — React и Vite. Интерфейс на русском
и узбекском языках (латиница).

## Что реализовано

- Пользователи, одна группа на пользователя, модули, разрешения и стартовые страницы.
- Справочники поставщиков и городов.
- Приём сырья несколькими партиями, отдельный анализ каждой партии, распределение
  одобренного объёма по приёмным бакам при завершении приёма.
- Движение жидкости до отдельных баков сырой солярки и сырой веретенки.
- Производственный обзор: реальные данные первых этапов и статичные дальнейшие схемы.
- Независимый складской учёт: поступления, внутренний расход, перемещения
  с подтверждением, инвентаризация, количественный и стоимостной учёт.
- База знаний с разделами, статьями и правами редактирования.

## Языки интерфейса

Выбор «Русский / O‘zbekcha» находится на странице входа и в верхней панели
каждой страницы. Выбор сохраняется в этом браузере, синхронизируется между
вкладками и не сбрасывает авторизацию, открытые формы или введённые значения.
По умолчанию используется русский.

Переводятся меню, схемы обзора, формы, фильтры, статусы, известные ошибки API,
системные названия и встроенные инструкции базы знаний. Форматы дат и чисел
соответствуют выбранному языку. Названия поставщиков, городов, товаров, складов,
комментарии и пользовательские статьи автоматически не переводятся и не меняются
в БД. При редактировании инструкции открывается её исходный текст; изменённая
инструкция больше не подменяется встроенным переводом.

Ресурсы переводов и общие функции находятся в `frontend/src/i18n/`.
Новые подписи добавляйте через `t()`, новый узбекский перевод — в каталог.
Дополнительные зависимости и миграции для переключения языка не нужны.

## Локальный запуск

### Подготовка

Нужны PostgreSQL, Python, совместимый с Django 6, и Node.js/npm, совместимые
с Vite 8. В локальном окружении при подготовке документации доступны Python 3.13
и Node.js 22. Зависимости зафиксированы в `requirements.txt` и
`frontend/package-lock.json`.

Создайте в корне локальный `.env`. Имена обязательных переменных:

```text
DJANGO_SECRET_KEY
DJANGO_DEBUG
DJANGO_ALLOWED_HOSTS
DJANGO_DB_NAME
DJANGO_DB_USER
DJANGO_DB_PASSWORD
DJANGO_DB_HOST
DJANGO_DB_PORT
```

Необязательная переменная `JWT_ACCESS_TOKEN_LIFETIME_MINUTES` задаёт срок JWT
в минутах; значение по умолчанию — 60. PostgreSQL-база и пользователь должны
существовать до запуска миграций. `.env` не публикуется; значения между окружениями
не копируются в код или документацию.

### Бэкенд

Из корня проекта:

```bash
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
./venv/bin/python sargon_erp/manage.py migrate
./venv/bin/python sargon_erp/manage.py runserver 127.0.0.1:8000
```

При необходимости создать администратора используйте интерактивную команду
`./venv/bin/python sargon_erp/manage.py createsuperuser`. Не добавляйте фиксированные
учётные данные в исходники или документацию.

### Фронтенд

В отдельном терминале из корня проекта:

```bash
cd frontend
npm ci
npm run dev
```

Откройте `http://localhost:5173`. Vite перенаправляет `/api` и `/ws` на локальный
бэкенд. Это режим разработки, не production-развёртывание.

## Проверки и развёртывание

Команды и ограничения тестирования собраны в [TESTING.md](docs/TESTING.md).
Существующий процесс развёртывания без Docker использует
`.github/workflows/deploy.yml` и `scripts/deploy.sh`: self-hosted runner,
ветка `main`, установка зависимостей, сборка, миграции, сбор статики и перезапуск
сервисов. Скрипт сохраняет `.env` и загруженные медиа.

Не запускайте этот скрипт как способ локальной проверки: он предназначен для
развёртывания. Внешний сервер не трогаем без отдельного разрешения пользователя.

## База знаний

Пункт «База знаний» открывает `/knowledge`: инструкции по приёму сырья, лаборатории,
переработке, складу, справочникам и доступам. Есть разделы, поиск по всему тексту,
пагинация по 10 статей и прямые ссылки на статьи (`/knowledge?article=<id>`).

Статьи и разделы хранятся в БД. Миграции `0030` и `0031` добавляют модели,
начальные инструкции и модуль `knowledge-base`. Применение:

```bash
./venv/bin/python sargon_erp/manage.py migrate
```

Существующие группы получают просмотр базы знаний; администраторы могут управлять
статьями и разделами. Для новых групп модуль и разрешения назначаются через
«Доступ → Группы». Создание, изменение и удаление проверяются на сервере.
Раздел со статьями удалить нельзя: сначала перенесите или удалите его статьи.

Текст поддерживает заголовки `##` и `###`, списки с `- ` или `1. ` и абзацы,
разделённые пустой строкой. HTML отображается как текст.
