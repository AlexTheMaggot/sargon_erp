# Проверки и регрессия

Актуализация: 2026-10-09. Это инструкция проверки, а не отчёт о выполненном прогоне.
В задаче подготовки документации тесты, миграции и браузерные операции не запускались.

## Безопасное окружение

- Работайте локально, без подключений к внешнему серверу.
- Не печатайте `.env`, JWT, пароли или реальные данные поставщиков в отчёт.
- Для ручных сценариев используйте согласованные тестовые записи и пользователей;
  не создавайте постоянные фиксированные учётные данные без запроса.
- Django-тесты создают отдельную PostgreSQL test-базу; подключение должно быть
  локальным/тестовым, а пользователь БД иметь права создания и удаления test-базы.
- Не подменяйте PostgreSQL на SQLite для проверки блокировок и конкурентных движений.
- Не выполняйте `migrate`, `flush`, очистку данных или деплой как необязательную
  часть чтения проекта. Изменения схемы применяются только по соответствующей задаче.

## Команды

Из корня репозитория:

```bash
./venv/bin/python sargon_erp/manage.py check
./venv/bin/python sargon_erp/manage.py makemigrations --check --dry-run
./venv/bin/python -m compileall -q sargon_erp
./venv/bin/python sargon_erp/manage.py test api --noinput
git diff --check
```

`compileall` создаёт игнорируемый байткод; Django-тесты временно создают/удаляют
test-базу. Не называйте эти команды исключительно чтением файлов.

Сначала можно запустить нужную область:

```bash
./venv/bin/python sargon_erp/manage.py test api.tests.ProductionAccountingTests --noinput
./venv/bin/python sargon_erp/manage.py test api.tests.ConcurrentMovementTests --noinput
./venv/bin/python sargon_erp/manage.py test api.tests.WarehouseAccountingTests --noinput
./venv/bin/python sargon_erp/manage.py test api.tests.KnowledgeBaseTests --noinput
```

При изменениях фронтенда:

```bash
cd frontend
npm run lint
npm run build
```

Сборка пишет в игнорируемый `frontend/dist/`; результат линтера/сборки не доказывает
правильную работу интерфейса. Отдельного автоматического UI-тестового набора сейчас нет.

## Ручные сценарии: подсказки логина

- В новом браузере до первого входа `datalist` получает весь список активных
  логинов с `/api/auth/login-options/`. Предыдущие успешные входы не требуются.
- Список отсортирован, не ограничен 10 строками; отключённых пользователей нет.
- Создание и отключение пользователя отражаются после перезагрузки формы.
- Публичный ответ содержит только `items` с логинами; ID, имён, групп, прав,
  контактов и паролей нет. Заголовок `Cache-Control` содержит `no-store`.
- Отказ сервера/сети показывает локализованную подсказку, но не блокирует ручной
  ввод логина и отправку формы входа. При уходе со страницы запрос отменяется.
- Список не записывается в `localStorage`; старая история логинов не используется.
- Проверить выбор подсказки и ручной ввод на десктопе и мобильной ширине,
  в русском и узбекском интерфейсах. Вид нативного списка зависит от браузера.
- `api.tests.LoginOptionsTests` проверяет публичность и минимальность ответа,
  активность, сортировку, полноту списка, свежесть данных, запрет кеширования,
  сохранение защиты `access/users/` и отклонение методов записи.

## Ручные сценарии: приём и лаборатория

Нужны два изолированных сеанса: менеджер приёма и лаборант. Два обычных окна одного
браузерного профиля используют общее хранилище JWT и не заменяют два аккаунта.

| Проверка | Ожидаемое поведение |
| --- | --- |
| Менеджер создаёт заявку с поставщиком | Одна партия и один анализ созданы автоматически; поставщик неизменяем |
| Попытка без выбранного поставщика | UI не отправляет форму либо показывает понятное объяснение; API отклоняет |
| Добавление второй/третьей партии | Отдельный анализ на каждую; порядковые номера корректны |
| Количество до одобрения | Ввести/сохранить нельзя |
| Лаборант заполняет анализ | Поля имеют подписи и единицы; сохранение не меняет решение само по себе |
| Одобрение неполных значений, плотность ≤ 0, вода вне 0–100 | Отклонение, решение не сохранено |
| Плотность вне мягкого диапазона | Предупреждение, но корректное одобрение не блокируется только из-за диапазона |
| Проверка при 20°C и 30°C | Диапазон меняется по текущей формуле; единица `г/см³` |
| Отказ по одной из нескольких партий | Эта партия заблокирована, остальные продолжают свой цикл |
| Изменение показателей/решения обычным лаборантом после решения | Запрещено на UI и API |
| По умолчанию открыть лабораторию | Только ожидающие решения; фильтры переключаются, выбранный текст читаем |
| Литры/килограммы после одобрения | Положительное количество сохраняется; килограммы пересчитаны по плотности |
| Распределение меньше/больше количества либо в полный/неактивный бак | Приём не завершён, объёмы не изменились |
| Одна партия в два бака | Сумма точно равна литрам партии; две записи движения |
| Успешное завершение | Дата сохранена, баки пополнены, повтор не пополняет снова |
| Все партии отклонены | Явное закрытие без распределения и без пополнения; не автоматическое закрытие по отказу |
| Изменение распределённой партии/анализа администратором | Запрещено |
| Удаление завершённого приёма администратором | Только с допустимой компенсацией, без потери истории |
| Удаление после движения из приёмного бака в котёл | Заблокировано |

## Синхронизация и звук

1. На открытой лаборатории создать у менеджера приём и дополнительную партию:
   новые анализы должны появиться без перезагрузки.
2. У лаборанта одобрить/отказать: у менеджера обновляются доступные действия и статус.
3. У менеджера удалить допустимую партию/приём: связанные анализы исчезают у лаборанта.
4. Проверить сохранение количества, завершение и изменение показателей:
   второй сеанс перечитывает актуальные данные.
5. Проверить WebSocket handshake и события, не копируя URL с JWT в отчёт.
6. Проверить резервный опрос до 15 секунд при отсутствии событий.
7. Звук: открытая лаборатория, взаимодействие пользователя, разрешённый звук вкладки;
   создание заявки/партии вызывает `notification.mp3`. Блокировка autoplay браузером
   не означает отсутствие самой новой записи.
8. Проверить отсутствие необработанных ошибок и повторяющихся подключений в консоли.

Не обещайте межпроцессную доставку на `InMemoryChannelLayer`. Такой тест требует
отдельного решения архитектуры, а не только перезагрузки вкладки.

## Производственная цепочка

Пройти приём → бак → котёл → сепаратор → химмиксер → цех → два разных бака
сырой продукции. На каждом движении сверять источник, назначение, литры,
пользователя, время и разницу остатков.

На каждом доступном маршруте проверить:

- ноль, отрицательный объём, более трёх дробных знаков;
- превышение остатка и переполнение назначения;
- неверный тип и неактивную ёмкость;
- двойное нажатие и повтор ключа идемпотентности;
- отмену администратором, повтор отмены, отсутствие/пустоту причины;
- попытку другого пользователя применить чужой ключ;
- неподдерживаемый метод и отсутствие права нужной формы.

Сепаратор: вода/мусор уменьшают общий остаток; ввод топлива через отгрузку запрещён.
Баки солярки и веретенки: объёмы и история раздельны. Нельзя выбирать бак другого вида.
Ёмкости: не удалять непустую/использованную, не уменьшать вместимость ниже остатка,
не деактивировать непустую; обычный оператор не управляет справочником.

## Склад

| Сценарий | Что сверять |
| --- | --- |
| Два поступления по разным ценам | Количество, средняя отдельно по складу, последняя закупочная цена |
| Одно наименование на двух складах | Средние не смешиваются |
| Расход до нулевого остатка | Отрицательное количество не возникает; средняя при нуле обнулена |
| Расход без назначения или сверх остатка | Документ/проведение отклонён, остатки прежние |
| Многопозиционный документ с нехваткой последней строки | Нет частичного проведения предыдущих строк |
| Отправка перемещения | Источник списан, назначения ещё нет, статус «В пути» |
| Подтверждение и отказ | Зачисление получателю либо возврат источнику по стоимости отправки |
| Повтор решения | Нет второго прихода/возврата |
| Нет `transfer-confirm` | Решение запрещено |
| Инвентаризация вверх/вниз/без разницы/в ноль | Движение только на разницу, либо отсутствует при равенстве |
| Ввод избыточной дробности единицы | Отклоняется, не округляется незаметно |
| Проведение вчера/завтра обычным пользователем | Запрещено; администратору разрешено |
| Отмена поступления/расхода/перемещения администратором | Обратные движения, сохранена история, корректный итоговый статус |
| Отмена при нехватке товара и повторная отмена | Отклонение без частичных изменений |
| Отмена после иных поступлений/расходов | Отдельно сверять количество, среднюю и стоимость, а не только статус |
| Справочник после использования | Защищённое удаление, доступность активных значений в формах |

Производственные объёмы не должны изменяться от складских операций и наоборот.

## Доступ и база знаний

- Проверяйте доступ с каждой целевой группой, а не только superuser.
- Для одной формы переработки: видны нужные источники/получатели, другие движения
  запрещены, управление ёмкостями и журнал недоступны.
- Для склада: `view` не даёт проводить документы, конкретное право разрешает
  только свой тип, настройки — отдельный модуль.
- Проверяйте прямой API-запрос и открытие URL вручную, не только скрытое меню.
- Проверяйте группу без модулей, неактивный модуль и пустой набор разрешений:
  последнее сейчас даёт просмотр, это важное исключение.
- Старт группы зависит от привязки, активности, `view` и существующего маршрута.
- База знаний: поиск по содержимому, разделы, страницы, прямая ссылка, CRUD
  с нужными правами, невозможность удалить используемый раздел, HTML как текст.
- Перед проверкой новой настройки прав обновите сведения о пользователе и сокет:
  открытый UI/соединение не обязаны мгновенно перечитать изменённую группу.

## Русский и узбекский интерфейс

- На входе переключите язык; подписи и ошибка неверных учётных данных должны
  соответствовать выбору. После входа и обновления страницы выбор сохраняется.
- Проверьте меню, обе схемы обзора и окна этапов, приём, лабораторию, все формы
  переработки и справочники ёмкостей, журнал, склад, справочники и страницы доступа.
- Переключите язык при открытой форме с введёнными значениями: поля, выбранные
  фильтры, текущая страница и авторизация должны сохраниться.
- Проверьте перевод известных ошибок сервера с параметрами: номер партии,
  недостающий объём, переполнение ёмкости, неверная точность количества.
  После смены языка уже показанная ошибка тоже должна переключиться.
- Названия поставщиков, городов, складов, товаров и пользовательские комментарии
  должны оставаться исходными; перевод нельзя отправлять обратно в API.
- Начальные инструкции базы знаний читаются и ищутся на выбранном языке.
  Пользовательские/изменённые статьи не подменяются переводом, редактор начальной
  инструкции открывает оригинал. Даты и числа форматируются по выбранной локали.
- Откройте вторую вкладку того же адреса: выбор должен синхронизироваться.
  Проверьте переключатель в шапке на настольном и узком экране.
- При добавлении подписи проверяйте наличие узбекского перевода; обозначения
  марок масел и другие пользовательские/технические идентификаторы не переводятся.

## PWA / standalone

- В разработке и сборке проверьте `/manifest.webmanifest` и три PNG в `/icons/`:
  корректный JSON/изображения, не HTML fallback. Манифест должен задавать
  `display: standalone`, `scope: /`, `start_url: /` и иконки 192/512 px.
- Кнопка установки доступна на странице входа и внизу бокового меню.
  Нативный диалог вызывается только по нажатию пользователя. Если событие установки
  не предоставлено браузером, открывается инструкция; отказ не является ошибкой.
- Проверьте русскую и узбекскую инструкцию, настольную и узкую ширину.
- На реальном Android/iOS устанавливайте только с доверенного HTTPS-origin.
  Запуск с домашнего экрана должен быть standalone, а не обычной вкладкой.
  localhost считается локальным только для того устройства, на котором открыт.
- В standalone кнопка установки скрыта. Вход, стартовая страница группы,
  переходы, выход и WebSocket должны сохранять обычную логику приложения.
- Не должно появляться зарегистрированного этим кодом service worker или
  service-worker-кеша API/документов. Работа без сети намеренно не поддерживается.
- Установку на реальном телефоне и наличие HTTPS проверяйте отдельно; сборка
  и манифест сами по себе не подтверждают эти результаты.

## Интерфейс и отчёт

Проверяйте настольный и узкий экран, боковое фиксированное меню, модальные формы,
видимые ошибки, подписи полей, radio-кнопки, выбранные фильтры и вкладки.
Для браузерной проверки используйте доступный Chrome/инструмент управления браузером;
не добавляйте тестовую зависимость ради одного ручного прогона.

В отчёте указывайте дату, окружение без секретов, роль, шаги, ожидаемое/фактическое,
идентификатор тестовой записи при необходимости, результат команд и ограничения.
Различайте: воспроизведённую ошибку, известное ограничение, предположение и улучшение UX.
Не удаляйте тестовые записи и не публикуйте отчёт с инфраструктурными подробностями
без соответствующего разрешения.
