# Решения и границы развития

Актуализация: 2026-11-06. Это не список заданий на реализацию.
Статус «реализация» означает наблюдаемое устройство кода, не отдельное утверждение
пользователя о каждом техническом выборе.

## Подтверждённые требования пользователя

| Решение | Причина / последствие |
| --- | --- |
| Django без DRF, JWT не через SimpleJWT | Сохраняем обычные Django views и PyJWT; не добавляем DRF ради удобства новых API |
| Одна группа на пользователя, группы ↔ модули | Права не назначаются напрямую пользователю; роль определяется настройками группы |
| Динамический старт группы | Не связываем стартовую страницу с жёстко заданным именем роли |
| Несколько партий в одном приёме | Каждая физическая порция может иметь независимый лабораторный результат |
| Анализ создаётся автоматически | Нет отдельного ручного создания анализа и сиротских заявок лаборатории |
| Количество только после одобрения | Приёмка учитывает решение по конкретной партии |
| Полный запрет изменения распределённой партии | После попадания в бак нельзя незаметно пересчитать уже проведённый объём |
| Мягкий диапазон плотности с температурной поправкой | Подсказка лаборанту вместо автоматического решения о качестве |
| Отдельный модуль каждой формы переработки | Можно выдать оператору ровно одну производственную операцию |
| Динамические производственные ёмкости | Количество оборудования не зашито в маршруты и права |
| Сырая солярка и сырая веретенка раздельно | Отдельные страницы, виды баков, маршруты и остатки |
| Универсальный склад отдельно от производственных жидкостей | Не дублируем текущие баковые остатки складскими документами |
| Динамические склады и единицы, без артикула пока | Справочники меняются через UI; точность единицы — 0/1/2 дробных знака |
| Сырьё, запчасти, готовая продукция | Три начальные категории, не автоматическая интеграция с производством |
| Денежный учёт в узбекских сумах без НДС | Одна валюта и количественно-стоимостные движения |
| Последняя закупочная цена в номенклатуре | Отдельна от средневзвешенной стоимости каждого склада |
| Средняя стоимость по каждому складу | Разные закупки/перемещения не смешивают оценку всех складов в одну |
| Поставщик обязателен при складском поступлении | Используется общий справочник поставщиков |
| Внутренний расход вместо продаж | Назначение пока свободным текстом; покупателей и продаж нет |
| Перемещение с подтверждением получения | При отправке товар «В пути»; отказ возвращает его источнику |
| Инвентаризация по фактическому остатку | Движение формируется автоматически на разницу |
| Отрицательные складские остатки запрещены | Проверка бизнес-логики и ограничение БД |
| Проведённые складские документы не удаляются | Только обратные движения; отмена пока только у администратора |
| Проведение другой датой только администратору | Обычный пользователь работает текущей локальной датой |
| Все склады видимы пользователю с правом просмотра | Пока без закрепления отдельных складов за пользователями |
| Один модуль склада с операционными разрешениями | `receipt`, `issue`, `transfer`, `transfer-confirm`, `inventory` внутри общего модуля |
| Настройки склада отдельным модулем | Операционные полномочия не дают управление справочниками |
| Локальная работа без самовольного деплоя | Сервер, push, CI/CD и внешние данные требуют отдельного поручения |
| PWA с акцентом на standalone | Установка и отдельное окно на устройстве, без внедрения offline-кеша рабочих данных |
| Без кнопок установки в интерфейсе | Кнопки страницы входа и бокового меню, подсказки и связанная логика удалены; возможность установки PWA через браузер сохранена |
| Полный список логинов до входа | Нативный `datalist` получает из БД логины всех активных пользователей, а не локальную историю; раскрытие логинов согласовано, остальные сведения не выдаются |
| Канистры и крышки на одной вкладке обзора | Вкладка «Производство канистр»: две линии, общие гранулы, раздельные красители и два непересекающихся контура вторсырья |
| Без отдельного пояснения об общих гранулах | Убран верхний блок общих гранул, указания на общий запас и нижний поясняющий абзац о браке; производственные связи сохранены |
| Отклонение канистр — складская позиция | Отдельный остаток и расход, не временная сортировка и не автоматический брак; у крышек отклонения нет |
| Возврат собственного брака только после измельчения | До измельчения брак обозначается в штуках, полученное вторсырьё — в кг и только в своём контуре |
| Постоянные производственные материалы на складе | Гранулы, красители и сорбент отображаются на закреплённых складах даже при нуле; назначение и склады задаются в номенклатуре |
| Выдача сырья при загрузке, не при выпуске | Проведённая загрузка списывает количество и сохраняет стоимость в складском расходе; выпуск не должен повторять это списание |
| Сорбент списывается только при передаче со склада | Циркуляция между баком и сорбент-системой не является новой складской выдачей; производственные жидкости остаются отдельными |
| Первый этап производственного учёта упаковки | Реализованы остатки сырья на участке и регистрация выпуска; фактический расход задаётся вручную по загрузкам, не рассчитывается из штук |
| Не выдумывать распределение себестоимости | Сохраняется стоимость использованного сырья, но автоматический складской приход изделий и распределение по годным/отклонениям/браку ждут согласования |

## Текущие технические решения

| Реализация | Важная граница |
| --- | --- |
| Сохранённый баланс плюс история движений | Не только вычисление суммы истории при каждом открытии; операция меняет оба источника согласованно |
| PostgreSQL-транзакции и блокировки для движений | Не заменять на последовательные независимые сохранения без транзакции |
| Компенсации производственных движений | История сохраняется, обратная операция проверяет доступные остатки и вместимость |
| JWT в `localStorage`, без refresh/revocation | Не считать выход из UI серверным отзывом токена |
| WebSocket плюс резервный HTTP-опрос | Сообщение инициирует загрузку данных, а не заменяет авторитетное состояние |
| In-memory channel layer | Межпроцессная доставка не обеспечивается; Redis не внедрён |
| Явное завершение полностью отклонённого приёма | Автозакрытие всего приёма по последнему отказу не внедрено; смешанный приём продолжает работу |
| Производственный обзор с частично реальными данными | Реальны переработка до готовых баков, загрузки/переливы товарных масел, розлив в литрах, сорбентный контур, отгрузки воды/мусора и учёт упаковки. Присадки, рециклинг упаковки и её складское оприходование не подключены |
| Замкнутый контур сорбента | Новый сорбент со склада пополняет общий бак; бак → сорбент-система → прогрев/очистка → бак. Масса учитывается вручную в кг, повторного складского списания нет |
| Продолжение переработки до готовых баков | Реализованы общая финишная линия и отдельные формы/модули; солярка и веретенка проходят её по очереди, пока все общие ёмкости не опустеют |
| Производство товарных масел | Веретенка + складской полипропилен → концентрат; концентрат + основа → смеситель → бак соответствующей марки → розлив |
| Присадки пока не учитываются | Последнее уточнение пользователя отменяет предварительное предложение списывать их: формы и складские списания присадок не добавляются |
| Выход по фактическому переливу | Отдельный ввод «получено» не нужен; кг не складываются с литрами, объём фиксируется при переливе. Завершение партии подтверждает пустое оборудование, без повторного измерения |
| Розлив только в литрах | Списание из продуктового бака без тары и автоматического складского прихода фасованного масла |
| Начальник смены | Все действующие производственные формы, старт рабочего места производства с тремя направлениями; без обзора, приёмки/лаборатории и административных полномочий. Настраивается обычными групповыми правами |
| Упрощённое рабочее место | Крупные карточки «Переработка масла», «Производство масла», «Производство канистр»; внутри кнопки существующих форм и явный возврат к направлению. Это не последовательный мастер и не изменение производственного учёта |
| Обзор ограничен модулем | `dashboard:view` обязателен на клиенте и сервере; доменные администраторы имеют обход. Прежний доступ прочих существующих групп сохранён миграцией |
| Справочники производственных ёмкостей изменяет только администратор | Обычные CRUD-права `used-oil-processing` не заменяют административный статус |
| Отдельная база знаний в БД | Markdown разработчика не синхронизирован со статьями автоматически |
| Неактивные модули исключаются, пустые права означают `view` | Пустой список прав нельзя использовать как запрет доступа |
| Один большой файл доменных views | Сервисный слой не выделен; документация помогает ориентироваться, но не является рефакторингом |
| PWA без service worker | Манифест и иконки сохранены, установка через браузер без собственного UI; нет офлайн-документов или дополнительного кеша API |

Подробности и проверяемые исключения — в [BUSINESS_RULES.md](BUSINESS_RULES.md)
и [ACCESS_CONTROL.md](ACCESS_CONTROL.md).

## Отложено, не поручено к внедрению

- Складские партии, сроки годности, сертификаты и ячейки.
- Минимальные остатки и уведомления о дефиците; резервирование не реализовано.
- Автоматическое оприходование готовой продукции из производства.
- Справочник подразделений/получателей: позднее можно добавить FK и сохранить
  прежний текст назначения для исторических документов.
- Учёт присадок, рецептур, технологических потерь и себестоимости товарного масла.
- Технологические потери, утилизация и оценка ресурса сорбента; промывка общей линии.
- Утверждённые нормы технологического выхода, состава, воды, мусора и потерь.

Не создавайте миграции, формы или новые задачи из этого списка без отдельного запроса.

## Когда действительно нужно спросить пользователя

Для описания текущей системы дополнительных обязательных ответов не требуется.
Вопрос нужен, если новая задача меняет важное правило:

- Нужно ли менять явное закрытие полностью отклонённого приёма на автоматическое?
- Какие утверждённые нормы состава/потерь и куда относить технологические отклонения,
  если добавляется материальный баланс производства?
- Требуется ли исторический перерасчёт себестоимости и какое правило отмены
  применять после последующих операций, если расширяется денежный учёт?
- Нужны ли мгновенный отзыв сессий и обновление прав уже подключённых клиентов,
  если меняются требования безопасности?

Это условия будущих решений, не подтверждённые требования и не блокировка
текущей документации. Технические детали, уже однозначные из кода, повторно не спрашиваем.
