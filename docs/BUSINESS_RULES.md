# Бизнес-правила

Актуализация: 2026-11-06. Описано фактическое поведение локального кода.
Права и административные исключения уточняются в [ACCESS_CONTROL.md](ACCESS_CONTROL.md).

## Общие принципы

- Производственные жидкости и универсальный склад учитываются независимо.
- Объёмы производственных ёмкостей — литры, до трёх знаков после запятой.
- Производство не обязано идти непрерывно по одной заявке: ёмкости накапливают
  общий объём, последующие загрузки оформляются отдельными движениями.
- Статусы лаборатории относятся к отдельным партиям, завершение — ко всему приёму.
- Остатки хранятся отдельно и меняются вместе с записями движения; не изменяйте
  их напрямую как замену операции. История нужна для проверки и восстановления.

## Справочники

Поставщик: название компании, город, адрес, телефон. Город — самостоятельная сущность.
Связь `Supplier.city` защищена `PROTECT`: используемый город удалить нельзя.
Поставщик также защищён ссылками из приёмов и складских документов.
Просмотр городов для выбора поставщика не означает права управлять городами.

## Приём сырья

### Заявка и партии

1. Менеджер выбирает поставщика и создаёт заявку.
2. Автоматически создаются партия №1 и её лабораторный анализ.
3. Дополнительные партии создаются отдельно с последовательным номером и своим анализом.
4. Поставщик заявки после создания неизменяем, в том числе для администратора.
5. Приём должен иметь хотя бы одну партию. Добавление партии в завершённый приём запрещено.

До одобрения анализа нельзя указать количество партии. Менеджер при этом может
управлять незавершённой заявкой и добавлять партии в пределах своих разрешений;
это не означает, что после создания ему запрещены вообще все действия.

### Количество

- Ввод — литры либо килограммы, выбор единицы в интерфейсе оформлен radio-кнопками.
- Количество должно быть положительным. Расчётное значение хранится в `quantity_liters`.
- Для литров результат округляется до `0.001` методом `ROUND_HALF_UP`.
- Для килограммов: `литры = килограммы / плотность`, затем такое же округление.
  Плотность отображается как `г/см³`; численно это эквивалентно `кг/л`.
- Итог приёма складывается из одобренных партий. Отклонённые партии не пополняют баки.

Партия с заполненным, но не одобренным анализом, с отказом или в завершённом
приёме блокируется для обычного пользователя. Распределённая партия и её анализ
неизменяемы даже администратором.

### Завершение и распределение

Необходимо окончательное решение по каждой партии. Каждая одобренная партия
должна иметь сохранённое положительное количество.

Менеджер распределяет каждую одобренную партию по одному или нескольким активным
приёмным бакам. Проверяется:

- положительный объём каждой строки с точностью до `0.001 л`;
- одна строка на пару партия/бак;
- точное равенство суммы распределения объёму соответствующей партии;
- правильный тип и активность баков;
- вместимость с учётом суммарной загрузки всех партий в каждый бак.

При успешном завершении создаются `receipt_to_tank` движения, увеличиваются
остатки баков, сохраняются `is_completed` и `completed_at`. Повторное завершение
через административно доступный путь не создаёт вторую загрузку.

Если отклонены все партии, приём закрывается менеджером явно, без распределений
и без движения жидкости. Отказ лаборатории сам по себе не закрывает весь приём.
Отклонение одной партии не запрещает принять другие одобренные партии того же приёма.
В модели нет отдельного статуса всего приёма «отказан»: результат определяется
завершением и решениями по партиям.

### Удаление

- Обычный пользователь не удаляет завершённый приём или заблокированную партию.
- Администратор может удалять в рамках серверных прав, но загруженные объёмы должны
  быть компенсированы, а история движений сохранена.
- Если из задействованного приёмного бака уже есть движение в котёл, удаление приёма/
  партии блокируется. Текущая проверка относится к истории всего бака, а не к
  прослеживаемому происхождению конкретных литров.
- Компенсация запрещается, если приводит к отрицательному остатку или переполнению.

## Лаборатория

### Показатели и решения

| Поле | Единица / ограничение |
| --- | --- |
| `density` | `г/см³`, при заданном значении больше нуля |
| `flash_point_temperature` | °C |
| `current_temperature` | °C |
| `water_percentage` | %, при заданном значении от 0 до 100 |

Ручное создание анализа и независимое удаление анализа запрещены. Анализ
создаётся вместе с партией и удаляется вместе с ней/приёмом.

Статусы, вычисляемые для интерфейса:

| Статус | Значение |
| --- | --- |
| `pending` | Не все показатели заполнены, решения нет |
| `filled` | Все показатели заполнены, решения нет |
| `approved` | Одобрено |
| `rejected` | Отказано |
| `missing` | Анализ отсутствует; защитная обработка неполных данных |

Для одобрения нужны все четыре корректных показателя. Одобрение и отказ
взаимоисключающие; `decided_at` сохраняет время решения. Обычному лаборанту
после решения запрещено менять и показатели, и статус. Административное изменение
возможно до распределения партии, с сохранением необходимых модульных прав.

По умолчанию страница показывает ожидающие решения записи (`pending` и `filled`);
доступны фильтры одобрено, отказано и все записи. Финальные записи остаются в истории.

### Мягкая проверка плотности

Это подсказка, а не автоматическое разрешение/отказ:

```text
при 20°C: 0.850–0.905 г/см³
поправка = 0.00065 × (текущая температура − 20)
минимум = 0.850 − поправка
максимум = 0.905 − поправка
```

При 30°C диапазон `0.8435–0.8985 г/см³`. Выход за диапазон подсвечивается,
но не блокирует решение. Коэффициент — используемое приложением значение,
не утверждение о нормативе предприятия или универсальной физической модели.
Система не принимает технологическое решение вместо лаборанта.

## Переработка

### Реализованные маршруты

| Операция | Источник → назначение | Тип движения |
| --- | --- | --- |
| Завершение приёма | Одобренная партия → приёмный бак | `receipt_to_tank` |
| Загрузка котла | Приёмный бак → котёл прогрева | `tank_to_boiler` |
| Загрузка сепаратора | Котёл → сепаратор | `boiler_to_separator` |
| Отгрузка сепаратора | Сепаратор → внешнее выбытие воды/мусора | `separator_output` |
| Загрузка химмиксера | Сепаратор → химический миксер | `separator_to_chemical_mixer` |
| Загрузка цеха | Химический миксер → цех переработки | `chemical_mixer_to_workshop` |
| Загрузка сырой солярки | Цех → бак сырой солярки | `workshop_to_raw_diesel_tank` |
| Загрузка сырой веретенки | Цех → бак сырой веретенки | `workshop_to_raw_spindle_tank` |
| Загрузка сорбент-системы маслом | Бак сырой солярки/веретенки → сорбент-система | `raw_to_sorption` |
| Загрузка финишного миксера | Сорбент-система → финишный миксер | `sorption_to_mixer` |
| Загрузка финишного фильтра | Финишный миксер → фильтр | `mixer_to_filter` |
| Загрузка готового бака | Фильтр → бак готовой солярки/веретенки | `filter_to_finished_tank` |

Для ручных загрузок требуются соответствующие типы активных ёмкостей,
положительный объём, достаточный остаток источника и место у получателя.
Баланс источника уменьшается, получателя увеличивается в одной транзакции
с созданием движения. Время движения и пользователь сохраняются сервером.

Ключ `idempotency_key` обязателен для ручных движений. Повтор принятого запроса
с тем же ключом от того же пользователя возвращает исходную запись без нового
списания. Использование чужого ключа отклоняется. Это не универсальная гарантия
идемпотентности для остальных подсистем.

Отгрузка сепаратора допускает только техническую воду и технический мусор.
Отгрузка топлива этим маршрутом запрещена. Объём отгрузки уменьшает общий
остаток выбранного сепаратора.

### Ёмкости и история

- Пятнадцать типов ёмкостей динамические; номер уникален внутри типа.
- Вместимость положительная и целая; текущий объём неотрицателен и не выше вместимости.
- Создание, изменение и удаление ёмкостей — только доменным администраторам.
- Уменьшать вместимость ниже текущего остатка и деактивировать непустую ёмкость нельзя.
- Удаляется только пустая ёмкость без истории; пустая с историей деактивируется.
- Журнал и компенсация производственных движений доступны администраторам.
- Компенсация создаёт обратное движение с обязательной причиной, не удаляет исходное;
  повторная компенсация и компенсация компенсации запрещены.

### Границы материального баланса

Учитываются общие объёмы. Нет прослеживаемой структуры состава смеси по исходным
партиям, обязательного выхода воды по лабораторному проценту, норм потерь и выхода
продуктов. Нельзя считать произвольное распределение выхода цеха нарушением
уже реализованного технологического норматива: такой норматив пока не задан.

## Обзор

Реальные данные: приём, приёмные баки, котлы, сепараторы, химические миксеры,
цеха, баки сырой солярки и сырой веретенки. Информация этапа открывается модально.
HTTP-обновление каждые 15 секунд, не гарантированное мгновенное обновление.

Финишная очистка и баки готовой солярки/веретенки подключены к реальному учёту.
Вода и мусор показывают реальные отгрузки сегодня/за всё время без компенсированных
операций, а не остаток накопителей. На схеме «Производство масла» подключены
загрузки открытых партий, измеренные переливы, продуктовые баки, складской
полипропилен и розлив; присадки явно помечены как не учитываемые.

### Общая линия финишной очистки

- Сорбент-системы, финишные миксеры и фильтры образуют одну общую линию:
  солярка и веретенка не могут одновременно находиться на разных её участках.
- Продукт определяется источником, не принимается на доверии из формы. В непустой
  общей ёмкости он сохраняется; после полного опорожнения сбрасывается.
- Другой продукт допускается только после опорожнения всех общих ёмкостей.
  Готовые продуктовые баки в эту блокировку не входят и остаются раздельными.
- Фильтр направляет продукт только в готовый бак соответствующего вида.
- Время, оператор и литры сохраняются; расход и приход выполняются атомарно.
  Повтор ключа возвращает исходное движение только при совпадении пользователя,
  операции, источника, получателя и количества; иначе HTTP 409.
- Компенсация только администратором, с причиной и обратным движением; проверяет
  остатки, вместимость, продукт и занятость общей линии, не смешивает продукты.
- Новые формы показывают историю своего типа всем с `view`, по 10 записей,
  и обновляют списки/историю каждые 15 секунд. Общий административный журнал сохранён.
- Оборудование создаётся администратором с фактическими вместимостями;
  миграции не создают фиктивные ёмкости или стартовые остатки.
- Это учёт перемещений, не управление автоматикой: прогрев, готовность, рецептуры,
  потери и промывка между продуктами пока не моделируются. Циркуляция сорбента
  учитывается отдельно от литров масла.
  Выдача сорбента со склада не повторяется при движении масла по линии.
Их показатели не являются реальными остатками. Складские остатки — отдельный экран.
Счётчик завершённых за день включает также завершённые приёмы с полностью
отклонёнными партиями; это не обязательно число успешных поступлений.

## Производство товарных масел

1. Оператор загружает веретенку из готового бака в реактор и указывает склад,
   номенклатуру полипропилена и кг. Списание основы и полипропилена атомарно;
   нехватка любого компонента откатывает всю операцию. Полипропилен — постоянная
   производственная номенклатура в кг, закреплённая за складом.
2. Загрузка смесителя задаёт марку масла, литры основы и фактически перелитые
   литры концентрата из открытой партии реактора. Нового складского списания
   полипропилена не происходит. Присадки пока не учитываются.
3. Перелив из открытой партии смесителя в продуктовый бак фиксирует фактически
   измеренные литры. Марка партии и бака должна совпадать; переполнение запрещено.
   Любой смеситель может направлять масло в любой подходящий по марке бак.
4. Розлив уменьшает остаток выбранного продуктового бака на указанные литры.
   Остаток не может стать отрицательным. Тара и складской приход фасованного
   продукта не создаются.

### Измерение и открытые партии

- Не прибавлять кг полипропилена к литрам и не выдумывать коэффициенты выхода.
- Фактический выход фиксируется только в форме перелива. Дополнительное поле
  «получено» или повторный ввод общего выхода не требуется.
- Реактор/смеситель показывают историю загрузки и измеренных переливов, не
  вычисленный остаток готовой смеси. Загрузка жидкостей и суммарные переливы
  одной партии не должны превышать вместимость оборудования.
- Партия остаётся открытой для нескольких переливов. После них оператор отдельно
  подтверждает полное опорожнение и завершает партию без ввода нового количества.
  Только затем оборудование допускает следующую загрузку.
- Даты открытия/закрытия и оператор сохраняются; поля закрытой партии не редактируются.
- Марки динамические. У непустого продуктового бака марка неизменна; в пустом её
  может переназначить администратор. Нельзя удалить марку со ссылками или отключить
  марку с остатком/открытой партией.
- Жидкостные и складские данные не удаляются: отмена партии администратором
  разрешена только до фактических выходящих переливов, с обязательной причиной.
  Она возвращает основу и полипропилен обратными движениями. Для возврата
  концентрата его исходная партия должна ещё быть открыта. Невозможный возврат
  откатывает отмену целиком.
- Компенсация перелива готового масла возможна при открытой партии, неизменной
  марке бака и достаточном остатке; розлива — при неизменной марке и наличии места.
  Отдельная компенсация загрузок запрещена: отменяется связанная партия.
- Повтор ключа с тем же пользователем и телом запроса не дублирует движения;
  изменение параметров с тем же ключом возвращает 409.
- Рецептуры, технологические потери, себестоимость литра масла и учёт присадок
  не вычисляются автоматически. Наличие форм не означает автоматизацию оборудования.

## Замкнутый контур сорбента

- Новый сорбент хранится на складе. Существующая «Загрузка сорбента» уменьшает
  складской остаток и зачисляет массу в общий производственный бак.
- Из бака оператор передаёт фактические кг в выбранную сорбент-систему; затем
  передаёт массу из этой системы на прогрев/очистку и возвращает очищенную массу
  в тот же общий бак. Частичные движения и повторные циклы разрешены.
- Внутреннее движение не создаёт складских расходов, приходов или новых закупочных
  цен. Подачи в разные системы и участки очистки различаются по системе и исходной
  складской выдаче. Новый сорбент не является обязательным для каждого нового цикла.
- Вводится фактическая масса с точностью выбранной единицы кг, максимум до сотых.
  Нельзя взять больше, чем доступно в конкретном источнике. Масса на всех участках
  вместе равна неотменённым пополнениям; потери, утилизация и изменение массы при
  очистке не предполагаются автоматически.
- Прогрев/очистка отмечаются передачей туда и возвратом; температурный режим,
  качество, ресурс и процент износа не рассчитываются. Не назначать вместимость
  сорбентного бака в кг на основании литров масляных ёмкостей.
- История содержит источник, систему, автора, дату, фактическое количество и
  комментарий. Движения не редактируются и не удаляются. Ключ повторного запроса
  защищает от двойного движения; изменённые параметры с прежним ключом запрещены.
- Администратор компенсирует движение отдельной обратной записью с причиной.
  Обратный источник должен иметь достаточный остаток; повторная компенсация
  запрещена. Для отмены складского пополнения сначала компенсируются все его
  действующие внутренние движения. Это не вторая выдача и не повторный возврат.
- Нельзя отключить систему с сорбентом в работе или на её участке очистки.
  История защищает систему от удаления даже после полного возврата в бак.
- Сорбентный учёт не меняет литры масла, не вводит новые требования к загрузке
  масла и не оформляет автоматически промывку линии между разными продуктами.
- На «Обзоре» показаны реальные кг в баке, системах и на очистке, без стоимости
  и вымышленных процентов ресурса. В форме пополнений остаётся накопленная выдача,
  а не количество сорбента непосредственно в баке.

## Складской учёт

### Справочники и ограничения

- Динамические склады, категории, единицы и номенклатура.
- Начальные категории: сырьё, запчасти, готовая продукция.
- Точность единицы: целые, десятые или сотые. Избыточная дробность отклоняется.
- Валюта только узбекский сум (`UZS`), суммы и цены до двух знаков; НДС не учитывается.
- Номенклатура хранит последнюю проведённую закупочную цену, не среднюю по системе.
- Пользователи с просмотром склада видят все склады; закрепления по складам нет.
- Продаж, покупателей, партий, сроков годности, сертификатов, ячеек, резервов
  и отдельной формы начальных остатков сейчас нет.
- Готовая продукция не поступает автоматически из производства. Существование
  категории не включает производственную интеграцию.

### Документы

Номер создаётся автоматически по типу и году даты документа:
`ПРХ` (приход), `РСХ` (расход), `ПРМ` (перемещение), `ИНВ` (инвентаризация),
затем год и шестизначный счётчик.

Документ содержит дату/время, тип, склады, поставщика при поступлении,
назначение внутреннего расхода, строки и сведения об авторах действий.
В документе хотя бы одна строка, номенклатура не повторяется.

| Документ | Обязательные данные | Эффект проведения |
| --- | --- | --- |
| Поступление | Склад-получатель, поставщик, количество, неотрицательная цена | Увеличение остатка, пересчёт средней, обновление закупочной цены |
| Внутренний расход | Склад-источник, текстовое назначение, количество | Уменьшение по средней стоимости источника |
| Перемещение | Разные источник и получатель, количество | Списание источника, статус «В пути» |
| Инвентаризация | Склад, фактическое количество, включая ноль | Только разница с текущим остатком на момент проведения |

Операции многопозиционного проведения атомарны: нехватка по строке отменяет всё
проведение. Отрицательный остаток запрещён бизнес-логикой и ограничением БД.
Черновик не влияет на остаток. Редактирование складского черновика через API
сейчас не реализовано; его можно удалить и создать заново с соответствующим правом.

### Производственные материалы и загрузки

- У номенклатуры настраивается назначение: гранулы, краситель или сорбент.
  Обычные товары, запчасти и готовая продукция остаются без такого назначения.
- Для производственного материала требуется активная единица кг и минимум один
  постоянный склад. На этих складах позиция видна и при нуле, даже до первого
  прихода; просмотр не создаёт фиктивных остатков или движений.
- Конкретные марки гранул и красители разных цветов создаются отдельными
  позициями, а не зашиваются в код. Миграции не создают материалы или склады
  и не классифицируют существующие товары по названию.
- В канистры и крышки выдаются гранулы и красители, на участок сорбции — только
  сорбент. Номенклатура должна быть закреплена за выбранным складом.
- Проведение загрузки сразу создаёт проведённый документ внутреннего расхода
  и движения по текущей средней стоимости склада. Хранятся направление,
  источник, номенклатура, количество, стоимость, автор, дата и комментарий.
- Проверка всех строк, списание и запись истории атомарны. Запрещены нехватка,
  нулевая/отрицательная величина и превышение точности единицы. Ключ запроса
  защищает от повторного списания; изменение данных с тем же ключом — конфликт.
- Проведённую загрузку нельзя изменить или удалить. Только администратор может
  отменить её обратным складским движением; повторная отмена не возвращает
  материал второй раз. Количество и исходная стоимость остаются в истории.
- Загрузка не создаёт готовую продукцию и не пересчитывает кг в штуки. Сорбент
  списывается только при выдаче со склада, не при циркуляции внутри контура.
  Циркуляция сорбента оформляется отдельными движениями; жидкости баков не затронуты.

### Остатки сырья в производстве и выпуск упаковки

- Источником является конкретное движение проведённой загрузки. Доступное
  сырьё = загруженное количество минус расход активных записей выпуска.
  Остаток вычисляется из истории, не сохраняется отдельным дублирующим балансом.
- При регистрации выпуска оператор явно выбирает фактический расход по
  загрузкам и результаты в целых штуках. Нормы рецептуры и вес изделия не заданы:
  система не вычисляет расход из количества штук и не делает обратный пересчёт.
- У изделий в номенклатуре задаётся линия канистр или крышек; требуется целая
  единица в штуках. Сырьё и изделие не могут быть одним назначением позиции.
  После появления истории назначение и единица защищены от переопределения.
- Канистры имеют три результата: годные, с отклонениями и брак. Крышки — только
  годные и брак. Отклонение — отдельный результат учёта, не временный статус
  и не автоматический брак. При будущем складском приходе оно должно иметь
  самостоятельную складскую позицию; такого прихода сейчас ещё нет.
- Выпуск потребляет только сырьё своей линии, не больше остатка конкретных
  загрузок. Количество и стоимость расхода сохраняются, склад не списывается
  повторно. Одна регистрация может содержать несколько изделий/результатов
  и несколько источников сырья. Все строки проводятся одной транзакцией.
- Стоимость фактического расхода берётся из исходных загрузок. При частичном
  использовании распределяется оставшаяся стоимость источника пропорционально
  расходу; последнее использование забирает весь оставшийся денежный остаток,
  чтобы не терять округлённые копейки. Это не распределение себестоимости
  между изделиями, годными, отклонениями или браком.
- Выпуск неизменяем, повтор защищён ключом запроса. Отмена только администратором
  сохраняет запись и строки, освобождая использованное сырьё внутри производства.
  Автоматического возврата на склад при этом нет. Отменить исходную загрузку
  нельзя, пока существует активный выпуск, использовавший её сырьё.
- В обзоре видны остатки сырья на каждой линии и накопленный зарегистрированный
  выпуск без отменённых записей. Число изделий здесь не складской остаток.
  Оприходование изделий, распределение себестоимости, измельчение и вторсырьё
  пока не реализованы и не подменяются фиктивными движениями.

### Расчёт средней стоимости

Расчёт отдельно по каждому складу и товару:

```text
новая средняя = (старое количество × старая средняя
                + поступившее количество × цена поступления)
               / новое количество
```

Средняя округляется до `0.01`. Расход и отправка берут текущую среднюю источника.
При нулевом остатке средняя обнуляется. При получении/возврате перемещения
используется стоимость, сохранённая при отправке, и пересчитывается средняя получателя.

При положительной инвентаризационной разнице используется текущая средняя,
а при её отсутствии — последняя закупочная цена. При отрицательной — средняя склада.
Итоговая стоимость документа в API выводится из цен его строк; для расхода,
перемещения и инвентаризации цены строк отсутствуют. Их фактическую оценку
не следует выводить из этого поля вместо стоимости движений.

### Статусы и подтверждение

```text
Поступление / расход / инвентаризация: draft → posted
Перемещение: draft → in_transit → completed или rejected
Отмена администратором: posted / in_transit / completed → cancelled
```

Отправленный товар отсутствует в доступных остатках обоих складов до решения.
Подтверждение добавляет его получателю; отказ возвращает источнику. Решение
требует отдельного `transfer-confirm`; повторное решение блокируется.

Обычный пользователь проводит только документ текущей локальной даты.
Ограничение распространяется и на будущую дату. Администратор может проводить
другой датой, но движения применяются к текущим остаткам: исторический перерасчёт
всех последующих документов и средней стоимости не реализован.

### Отмена

Проведённые документы не удаляются. Только администратор создаёт обратные
движения и переводит разрешённый статус в `cancelled`. Если отмена потребует
недоступного количества, она отклоняется целиком. `rejected` перемещение не входит
в разрешённые для отмены статусы текущего endpoint.

Текущая отмена корректирует количество через общие функции добавления/списания,
а обратные движения сохраняют исходную стоимость. Это не пересчёт всей истории
стоимости задним числом; точность оценки после последующих операций — отдельный
сценарий проверки, не доказанная этой документацией гарантия.

## База знаний

- Разделы и статьи хранятся в PostgreSQL, а не в Markdown репозитория.
- Начальное наполнение: шесть разделов и одиннадцать инструкций.
- Поиск по заголовку, краткому описанию и содержимому; фильтр по разделу;
  пагинация по десять статей; ссылка `/knowledge?article=<id>`.
- Управление зависит от `knowledge-base`: стандартные CRUD-права либо доменный администратор.
- Раздел со статьями удалить нельзя; автора/редактора статьи и даты хранит сервер.
- Поддерживаются абзацы, заголовки `##`/`###`, маркированные и нумерованные списки.
  HTML отображается как текст, выполнение HTML/скриптов не предусмотрено.
- Seed `0031` не заменяет пользовательские изменения существующих статей при своём
  выполнении. Обычный запуск `migrate` не запускает применённый seed повторно.
