# Архитектура

Актуализация: 2026-10-10. Описана текущая локальная реализация, не целевая архитектура.

## Компоненты

```text
React + React Router
  ├─ HTTP JSON /api/ → Django views → PostgreSQL
  └─ WebSocket /ws/operations/ → Django Channels

Локально: Vite проксирует HTTP и WebSocket на бэкенд.
Развёртывание: отдельная сборка фронтенда и существующие серверные сервисы.
```

- Django 6, без Django REST Framework. Ответы API формируются через `JsonResponse`.
- PyJWT: JWT доступа с HS256; ключ — `settings.SECRET_KEY` из окружения.
- PostgreSQL: модели, ограничения целостности, транзакции и блокировки строк.
- Channels/Daphne: ASGI и уведомления операций приёма/лаборатории.
- React 19, JavaScript/JSX, React Router, Vite 8. Бренд — SHENOLL;
  технические имена `sargon_erp` и ключ `sargon_access_token` сохраняются.

PWA — online-only оболочка существующей SPA. Service worker и отдельный кеш
не используются; API, JWT, маршруты, групповые стартовые страницы и WebSocket
не изменяются. Событие установки хранится в общем frontend-store, чтобы не
теряться при переходе со страницы входа в основное меню. Подробности установки
и требований HTTPS — в корневом README.

Нет отдельного сервисного слоя для доменных операций: сейчас логика находится
в функциях `views.py`. Не описывайте желаемое разделение как уже реализованное.

## Связи данных

### Доступ и справочники

```text
User 1 → 1 UserProfile → 0..1 AccessGroup
AccessGroup ↔ Module через GroupModuleAccess
GroupModuleAccess ↔ Permission
AccessGroup → 0..1 start_module (Module)

City 1 → N Supplier
Supplier 1 → N RawMaterialReceipt
```

Профиль создаётся сигналом при сохранении пользователя. Пользователь может быть
без группы. Прямой связи пользователя с модулями нет.

### Приём и производство

```text
RawMaterialReceipt 1 → N ReceiptBatch 1 → 1 LaboratoryAnalysis
ReceiptBatch → N MaterialMovement → ProductionContainer
ProductionContainer → N входящих/исходящих MaterialMovement
MaterialMovement → 0..1 компенсируемое MaterialMovement
```

- Старое nullable-поле `LaboratoryAnalysis.receipt` сохранено для совместимости;
  новые анализы привязываются к партии через `batch`.
- `ProductionContainer.kind` различает семь видов ёмкостей. Общая модель не означает
  взаимозаменяемость типов: каждый маршрут проверяет источник и назначение.
- Баланс хранится в `current_volume_liters`; история — в `MaterialMovement`.
- История хранит пользователя, время, объём, связи и текстовые снимки названий,
  остатки до/после, ключ идемпотентности и сведения о компенсации.
- `OperationAuditLog` отдельно хранит действия и некоторые отклонённые операции.
  Это не универсальный аудит всех изменений всех сущностей.

### Независимый склад

```text
InventoryCategory / UnitOfMeasure → InventoryItem
Warehouse + InventoryItem → WarehouseBalance (уникальная пара)
WarehouseDocument → N WarehouseDocumentLine → InventoryItem
WarehouseDocument → N WarehouseMovement → Warehouse + InventoryItem
WarehouseDocumentSequence → номер по типу документа и году
```

Склад не связан с производственными балансами автоматически. Поставщики общие.
Средняя стоимость хранится по паре склад/номенклатура; последняя закупочная цена —
в карточке номенклатуры.

### База знаний

`KnowledgeCategory 1 → N KnowledgeArticle`. У статьи есть заголовок, краткое описание,
текст, автор, последний редактор и даты. Удаление используемого раздела защищено.
Статьи — обычный текст с ограниченным форматированием, не произвольный HTML.

## Локализация интерфейса

- `frontend/src/i18n/core.js` содержит выбор `ru`/`uz`, перевод обычных строк
  и шаблонов, форматы локали и уведомление подписчиков. Русский — язык по умолчанию,
  узбекский использует латиницу. `useLanguage()` подписывает React на изменения.
- `LanguageSwitcher` доступен до и после входа. Выбор хранится в `shenoll_language`
  и синхронизируется событием `storage`; атрибут языка HTML обновляется.
  Смена языка не перезагружает страницу и не меняет JWT, маршруты или права.
- `uz.js`, `ru.js`, `serverMessages.js`, `systemMessages.js` содержат переводы
  интерфейса, известных ошибок и системных обозначений. Исходные сообщения API
  и значения в БД не изменяются. Новую ошибку API нужно добавить в словарь.
- `localizeStaticData()` предназначена только для статичных конфигураций схем
  и форм. Пользовательские названия, комментарии и значения полей остаются исходными.
- `knowledgeGuides.js` содержит переводы начальных инструкций. `knowledge.js`
  применяет их только при точном совпадении исходных заголовка и содержимого.
  При изменении статьи показывается авторский текст; редактор всегда сохраняет
  исходные данные, не перевод представления. Страница базы знаний загружается
  отдельно, чтобы инструкции не увеличивали начальную загрузку остальных экранов.
- Даты и числа отображаются через `getLocale()` (`ru-RU`/`uz-Latn-UZ`). Единицы
  переводятся только в подписях; числовой смысл и единицы хранения не меняются.

## Основные API

Все пути ниже начинаются с `/api/`, все идентификаторы в угловых скобках — переменные.
Точные маршруты и методы проверяются по `api/urls.py` и соответствующим views.

| Подсистема | Пути |
| --- | --- |
| Авторизация | `auth/login/`, `auth/me/` |
| Доступ | `access/users/`, `groups/`, `modules/`, `permissions/` и детали |
| Справочники | `directories/cities/`, `directories/suppliers/` и детали |
| Приём | `raw-material/receipts/`, `receipts/<id>/batches/`, `raw-material/batches/<id>/` |
| Лаборатория | `laboratory/analyses/`, `laboratory/analyses/<id>/` |
| Ёмкости | `processing/receiving-tanks/`, `preheating-boilers/`, `separators/`, `chemical-mixers/`, `workshops/`, `raw-diesel-tanks/`, `raw-spindle-tanks/` — все под `processing/` |
| Деталь ёмкости | `processing/containers/<id>/` |
| Движения | `processing/movements/tank-to-boiler/`, `boiler-to-separator/`, `separator-output/`, `separator-to-chemical-mixer/`, `chemical-mixer-to-workshop/`, `workshop-to-raw-diesel-tank/`, `workshop-to-raw-spindle-tank/` — все под `processing/movements/` |
| История и компенсация | `processing/journal/`, `processing/movements/<id>/compensate/` |
| Обзор | `dashboard/overview/` |
| Складские справочники | `warehouse/settings/categories/`, `units/`, `items/`, `warehouses/` — все под `warehouse/settings/` |
| Склад | `warehouse/reference-data/`, `warehouse/overview/`, `warehouse/documents/` |
| Складские действия | `warehouse/documents/<id>/post/`, `transfer-decision/`, `cancel/` — под тем же документом |
| База знаний | `knowledge/categories/`, `knowledge/articles/` и детали |

Большинство списков возвращает весь разрешённый набор; фронтенд ищет подстроку
без учёта регистра и делит его на страницы по 10. Это не серверная пагинация.
Журнал производственных операций имеет серверные фильтры и пагинацию, но
формирует объединённый список до разбиения на страницы.

## Авторизация и безопасность транспорта

- HTTP использует `Authorization: Bearer <JWT>`; фронтенд хранит JWT в `localStorage`.
- Вход возвращает токен и пользователя с `access`, `is_admin`, `start_path`.
- Поле логина связано с нативным `datalist`: до 10 последних уникальных логинов
  успешных входов хранятся только в браузере (`shenoll_login_history`). Список
  сохраняется после выхода; пароли в него не записываются. Публичного API списка
  пользователей нет, произвольный логин по-прежнему можно ввести вручную.
- `/auth/me/` используется при восстановлении сессии. Refresh-токенов и серверного
  отзыва токена при выходе сейчас нет: выход удаляет локальное состояние.
- Не обещайте немедленный отзыв уже выданного JWT при смене пароля/отключении
  пользователя: отдельного механизма отзыва здесь нет, проверку активности при
  декодировании надо учитывать в отдельном аудите.
- Скрытое меню не является защитой API; детали прав — в [ACCESS_CONTROL.md](ACCESS_CONTROL.md).

## Синхронизация

| Экран | Текущее обновление |
| --- | --- |
| Приём и лаборатория | Событие WebSocket и повторная загрузка HTTP; резервный опрос каждые 15 секунд |
| Обзор производства | HTTP-опрос каждые 15 секунд |
| Формы переработки | Загрузка при открытии и после собственного действия |
| Складские документы | Загрузка при открытии и после собственного действия |
| Складские остатки | Загрузка при открытии |
| База знаний | Загрузка при открытии и обновление локального состояния после собственного CRUD |

WebSocket: `/ws/operations/?token=<JWT>`. События содержат тип и идентификаторы;
авторитетные данные клиент перечитывает через HTTP. `receipt_created` и
`batch_created` вызывают звуковое уведомление на странице лаборатории. Звук зависит
от разрешённого браузером воспроизведения после взаимодействия пользователя.

`InMemoryChannelLayer` работает внутри одного процесса, а не между несколькими
worker-процессами. WebSocket проверяет доступ при подключении; не считайте смену
прав мгновенным переподключением существующего сокета. Не сохраняйте JWT из URL
сокета в диагностических отчётах или логах.

## Целостность, время и миграции

- Производственные распределения/перемещения и складские проведения используют
  транзакции и блокировки. Не все обычные CRUD-цепочки заключены в одну транзакцию;
  нельзя распространять гарантии защищённых движений на все endpoints.
- `Decimal` используется для доменных количеств и стоимости; значения сериализуются
  строками. В UI форматирование и мягкие предупреждения могут использовать `Number`.
- `USE_TZ=True`, локальный пояс `Asia/Samarkand`. Отбор «сегодня» использует локальную дату.
- Есть squash-миграция `0001_squashed_0016_seed_used_oil_processing`, заменяющая
  `0001`–`0016`; исходные миграции оставлены. Не удаляйте их и не меняйте применённые
  миграции без отдельной проверки истории всех окружений.
- `0027` выделяет формы переработки, `0028`/`0029` добавляют склад,
  `0030`/`0031` — базу знаний. Номер последней миграции не доказывает её применение
  на внешнем сервере.

## Развёртывание

Существующий workflow запускается на push в `main` и вручную, использует self-hosted
runner. `scripts/deploy.sh` блокирует параллельный запуск, синхронизирует исходники,
устанавливает зависимости, собирает React, выполняет миграции, `collectstatic`,
`check`, перезапускает приложение и перечитывает Nginx.

Сохраняются production `.env`, медиа, виртуальное окружение и каталоги зависимостей/
сборки. Текущий скрипт не является резервным копированием БД или автоматическим
откатом миграций. Конфигурация конкретного сервера не проверялась при документации.
